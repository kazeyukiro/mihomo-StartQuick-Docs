# 图形客户端

不想每天敲命令时，可以用带界面的程序。它们多半**内置或调用 Mihomo 核心**，界面负责订阅、切换节点、开系统代理 / TUN。

官方罗列（维护状态以该页为准）：  
https://wiki.metacubex.one/startup/client/client/

下面不推销具体软件，只说接的时候容易混的点。

---

## 内核和外壳

| | 谁 |
| --- | --- |
| 核心 | 真正做代理、读 YAML 的 mihomo 进程 |
| 外壳 | 按钮、订阅管理、托盘图标 |

出问题要先分清：  
- 界面打不开、订阅导入失败 → 多半找**客户端**项目  
- 规则不生效、协议报错、内核崩溃 → 看日志里是否是**核心**行为，必要时对照官方 wiki

有的客户端能换核心版本；升级外壳不等于核心一定是最新。

---

## 你通常要提供什么

和手写配置是同一套信息，只是填在界面里：

- **订阅链接**，或单个节点（服务器、端口、协议、密码/uuid…）
- 是否开**系统代理**（相当于给系统指 mixed-port）
- 是否开 **TUN**（系统级接管，需要权限）
- 规则模式还是全局（对应 `mode: rule` / `global` 一类）

若客户端支持「打开配置目录 / 编辑配置」，改的仍是核心在读的那份 YAML（或它生成的等价物）。

---

## 和命令行核心并存时

同一台机器上：

- 不要两个东西抢同一个 `mixed-port`
- 系统代理只能指向一个端口
- TUN 更不宜叠多个

要么用客户端托管核心，要么自己 `mihomo -d ...` 跑，选一条路。

---

## 面板

部分客户端自带界面；也可以让核心开 `external-controller`，用浏览器打开 Metacubexd / Yacd 等（见安装章）。  
API 只绑 `127.0.0.1` 更安全；对局域网开放时务必设 `secret`。
