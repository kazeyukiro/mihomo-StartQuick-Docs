# 一条请求怎么走完

前面几章把名词拆开讲了。这一章把它们串成一条线。

下面是简化图（省略了很多细节）：

```text
浏览器 / App
    │
    │  ① 流量怎么进 Mihomo？
    ▼
mixed-port / 系统代理 / TUN / …
    │
    │  ② 域名要不要先解析？（DNS，可能还有 fake-ip）
    ▼
规则 rules（从上往下，命中就停）
    │
    ├─ DIRECT  ──► 直连目标
    ├─ REJECT  ──► 丢掉
    └─ 某个组名 ──► 代理组选节点 ──► 具体节点 ──► 代理服务器 ──► 目标
```

---

## ① 入站：流量从哪进来

常见两种：

- **mixed-port（或 port / socks-port）**  
  只有「设置了代理」的程序才会进来。浏览器插件、系统代理指到 `127.0.0.1:7890` 这类。

- **TUN**  
  系统里一大块流量被虚拟网卡吸进来，很多软件不用单独设代理。权限和排错成本更高。

还有 `listeners`、redir、tproxy 等，进阶再用。

---

## ② DNS：规则经常要靠域名

访问的是 `example.com` 时，内核往往要知道对应 IP，或者用 fake-ip 先给一个假地址再往后处理。

所以 DNS 不是装饰：解析错了，后面 `GEOIP`、部分规则、真实连接都会跟着错。  
节点自己的域名，应用 `proxy-server-nameserver` 去解析，避免「连节点还依赖节点」的死结——配置参考 DNS 章有写。

---

## ③ 规则：决定去向

`rules` 从上到下匹配。  
策略写的是**组名**或内置名（`DIRECT` / `REJECT` 等），一般不要写死某一个节点名。

和 Xray 有一点不同：Xray 常把「没命中的流量」默认丢给**第一个 outbound**；Mihomo 在 `mode: rule` 下通常靠最后的 **`MATCH,某策略`** 显式兜底。别混用两套习惯。

---

## ④ 代理组：组里用谁

规则命中 `PROXY` 之后，由这个组的 `type` 决定：

- `select`：你在面板里选
- `url-test` / `fallback` / …：按延迟或顺序自动选

组里的成员来自手写 `proxies`，或 `use` 引用的订阅集合。

---

## ⑤ 节点：真正连出去

`proxies` 里一项 = 一套协议参数（服务器、端口、密码/uuid 等）。  
连的是远端代理；代理再去访问目标网站。

---

## 和配置文件的对应

| 步骤 | 配置里大致在哪 |
| --- | --- |
| ① 入站 | `mixed-port` / `tun` / `listeners` |
| ② DNS | `dns:` |
| ③ 规则 | `rules:` |
| ④ 组 | `proxy-groups:` |
| ⑤ 节点 | `proxies:` / `proxy-providers` |

读别人配置时，可以按这五步对号入座，而不是从第一行 YAML 硬啃到最后一行。
