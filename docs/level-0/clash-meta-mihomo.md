# Clash、Clash Meta、Mihomo 是什么关系？

名字一多就容易晕。先记结论：

> **你现在学的这个内核，正式名字叫 Mihomo。**  
> **Clash Meta 是它改名前的常用叫法。**  
> **Clash（原版）是更早的另一套项目，已经停更。**

下面按时间线拆开说。

---

## 一张表

| 名字 | 大致是什么 | 现在还维护吗 |
| --- | --- | --- |
| **Clash**（原版，Dreamacro） | 早期开源代理核心，YAML 配置、规则分流这套玩法很多从它传开 | **否**，约 2023 年底停更 / 归档 |
| **Clash Premium** | 原版作者做过的增强版（部分闭源） | 随原版一起退出日常讨论 |
| **Clash Meta** / **Clash.Meta** | 社区在原版思路上继续开发的分支，协议和支持面更广 | 已**改名**，项目还在 |
| **Mihomo** | Clash Meta **改名之后**的正式项目名（MetaCubeX） | **是**，当前主线 |

所以：

- 搜「Clash 配置」「Clash 订阅」——说的往往是**这一套 YAML 生态**，不一定还是 2022 年那个原版二进制。
- 搜「Clash Meta」「Meta 内核」——和 **Mihomo 是同一条线**的前后名字。
- 下二进制、看官方 wiki——认 **Mihomo** / [MetaCubeX/mihomo](https://github.com/MetaCubeX/mihomo) 即可。

---

## 为什么会改名

原版 Clash 停更之后，社区里实际还在演进的主力是 Meta 这一支。  
项目后来把仓库和程序名改成 **mihomo**，文档站也按新名字走。

改名原因对外说法不一，对使用者影响很简单：

- 配置大体仍是 Clash 风格的 YAML（`proxies` / `proxy-groups` / `rules` / `dns`…）
- 协议和功能在原版基础上多了很多（具体以当前版本为准）
- 网上旧教程仍写「Clash Meta」很正常，多数情况下可以当成在说现在的 Mihomo

---

## 和「某某 Clash 客户端」的关系

**Clash / Mihomo 首先是内核**（命令行程序），不是某一个带窗口的 App。

带界面的软件（各种 Verge、FlClash、Android 上的 Meta 客户端等）往往是：

```text
图形界面（订阅、开关、托盘）
        ↓
   调用内核（今天多半是 Mihomo）
```

所以会出现：

- 软件名字里还带「Clash」
- 设置里写「Meta 内核」或「mihomo」
- 实际跑的是同一类核心

换客户端 ≠ 换了一套完全不同的配置语言；换内核版本才更可能影响「新协议能不能用」。

官方对下游命名有要求：与 MetaCubeX 无关的项目，**名称里不得包含 mihomo**。  
见 wiki 首页说明。看到名字很像官方、仓库却对不上时，自己多留个心眼。

---

## 配置能不能通用

| 情况 | 大概怎样 |
| --- | --- |
| 老 Clash 的简单配置（少量节点 + 规则） | 很多仍能在 Mihomo 里跑，或只改几处 |
| Meta / Mihomo 专用字段（较新协议、部分 DNS/TUN 写法） | 原版 Clash **读不了** |
| 订阅 | 看订阅生成的是哪类节点；内核太旧会不认新协议 |

本站示例和字段说明都按 **当前 Mihomo** 写。拿十年前的「原版 Clash 教程」逐字抄，可能对不上。

---

## 你只要记住三句

1. **Mihomo = 现在的正式内核名**（以前常叫 Clash Meta）。  
2. **原版 Clash 已经停更**，别再追那个老仓库当更新来源。  
3. **客户端是壳，Mihomo 是芯**；本站讲的是芯怎么理解和怎么配。
