# 流量是怎么进到 Mihomo 的？

前面讲的都是「进来之后怎么处理」。  
还有一个更基础的问题：

> 流量是怎么进到 Mihomo 的？

---

## 最常见的几种方式

### 1. 系统代理 / 软件手动设置代理

Mihomo 监听一个端口（比如 `mixed-port: 7890`），  
你的浏览器或者系统设置成「HTTP/SOCKS 代理 `127.0.0.1:7890`」。

这是最传统、最安全的方式。只有设置了代理的软件才会走 Mihomo。

配置里常见写法：

```yaml
mixed-port: 7890
# 或者分开写
# port: 7890
# socks-port: 7891
```

`mixed-port` 的意思是：同一个端口同时支持 HTTP 和 SOCKS。

### 2. TUN 模式

TUN 是一个虚拟网卡。  
Mihomo 创建这个虚拟网卡之后，系统大部分流量都会被它「吸」进去。

好处：几乎所有软件都能被代理，不用一个个设置。  
坏处：需要管理员 / root 权限，配置相对复杂，出问题更难排查。

官方 wiki 的 TUN 章节有详细说明。新手建议先把普通 `mixed-port` 跑通，再去碰 TUN。

### 3. 其他入站

还有 `redir-port`、`tproxy-port`，以及各种 protocol inbound（让别人用 VMess / VLESS 等方式连你）等等。  
这些属于进阶用法，零基础阶段可以先不管。

---

## 现在只需要记住

```text
流量进来的方式（入站）
        ↓
规则判断
        ↓
代理组选节点
        ↓
真正连出去
```

入站决定「谁的流量能进 Mihomo」，规则和组决定「进来之后怎么走」。
