# 规则和代理组是什么？

这两个是 Mihomo 最核心的两块。

先用一句话区分：

> **规则决定「走哪条路」**  
> **代理组决定「这条路里具体用哪个节点」**

---

## 什么是规则？

规则就是一张「交通指示牌」。

你告诉 Mihomo：

- 如果目标是 example.com → 走 PROXY
- 如果目标是国内 IP → 走 DIRECT
- 其他全部 → 走 PROXY

配置里大概长这样：

```yaml
rules:
  - DOMAIN-SUFFIX,example.com,PROXY
  - GEOIP,CN,DIRECT
  - MATCH,PROXY
```

规则是**从上往下匹配**的，命中一条就停。  
所以顺序很重要。官方 wiki 的 Rules 章节写得很细，支持域名、IP、进程名、端口等等很多匹配方式。

对新手来说，先理解「规则 = 决定流量去向」就够了。

---

## 什么是代理组？

假设你有十几个节点。如果规则里直接写死「这个网站用日本节点 A」，那换节点的时候就要改规则，非常麻烦。

于是就有了**代理组**。

你先把节点丢进一个组：

```yaml
proxy-groups:
  - name: PROXY
    type: select
    proxies:
      - 日本
      - 香港
      - 新加坡
      - 美国
```

然后规则只写：

```yaml
- DOMAIN-SUFFIX,google.com,PROXY
```

意思是：这个流量交给叫 PROXY 的组去处理。  
组里具体用哪个节点，由组的类型决定。

常见类型（官方 wiki 都有）：

| 类型 | 人话解释 |
| --- | --- |
| `select` | 你自己在界面上手动选 |
| `url-test` | 定时测延迟，自动选最快的 |
| `fallback` | 按顺序试，能用的就用 |
| `load-balance` | 负载均衡，把流量分到多个节点 |
| `relay` | 代理链（高级用法） |

所以：

> 规则负责「分流」，代理组负责「在分好的那一类里怎么选节点」。

---

## 完整流程再看一遍

```text
请求进来
   ↓
规则匹配（决定交给哪个组 / 直连 / 拒绝）
   ↓
代理组（决定用组里的哪个节点）
   ↓
具体节点（真正去连接代理服务器）
   ↓
目标
```

配置文件里那三块对应关系：

| 配置 | 解决的问题 |
| --- | --- |
| `proxies` | 我有哪些节点 |
| `proxy-groups` | 节点怎么组织、怎么自动选 |
| `rules` | 流量怎么分流 |

把这张表印在脑子里，看别人配置就不会那么懵了。
