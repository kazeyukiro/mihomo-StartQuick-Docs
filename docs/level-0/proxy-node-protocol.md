# 代理、节点、协议到底是什么？

这三个词新手最容易混。

我们一个一个拆。

---

## 什么是「代理」？

最直白的说法：

> 代理就是「帮你转发请求的中间人」。

正常情况：

```text
你的设备  →  目标网站
```

用了代理之后：

```text
你的设备  →  代理服务器  →  目标网站
```

代理服务器站在中间，替你去访问目标。目标看到的是代理的 IP，而不是你的真实 IP（在理想情况下）。

---

## 什么是「节点」？

「节点」在日常说话里，几乎就等于「一个具体的代理服务器」。

比如别人说「我有个日本节点」「这个香港节点延迟低」，意思就是：

> 有一台在日本 / 香港的服务器，可以用某种协议连上去，帮你转发流量。

在 Mihomo 的配置里，一个节点长这样（简化版）：

```yaml
proxies:
  - name: Japan
    type: vless
    server: example.com
    port: 443
    # 后面还有 uuid、tls 等等一堆参数
```

这里的 `name` 就是你给它起的名字，`type` 是协议，`server` + `port` 是地址。

对新手来说，先记住：

> **节点 = 一个可以用的代理服务器配置。**

---

## 什么是「协议」？

协议就是「双方约定好怎么说话」。

就像人要交流，得用同一种语言。代理也一样，客户端和服务器得约定好用哪种方式加密、握手、传数据。

常见的有：

- Shadowsocks（ss）
- VMess
- VLESS
- Trojan
- Hysteria / Hysteria2
- TUIC
- 等等

官方 wiki 的 Proxies 章节里列得很全。不同协议有不同的字段，有的还支持插件（obfs、v2ray-plugin 等）。

你现在不需要把每种协议都背下来。只需要知道：

```text
协议  →  怎么说话
节点  →  跟谁说话、在哪里找到他
```

两者合在一起，才是一个完整的「可以用的代理」。

---

## 三者放在一起看

```text
协议：规定通信方式
节点：具体的一台（或一组）代理服务器
代理：用这个节点转发流量这件事本身
```

在 Mihomo 里，你写在 `proxies` 下面的每一项，就是「一个节点」。  
规则和代理组会引用这些节点的名字，决定流量到底走哪一个。

看到这里，你已经可以开始「读懂」最简单的 Mihomo 配置了。
