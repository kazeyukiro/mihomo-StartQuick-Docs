# Mihomo 到底是什么？

先别急着看配置。

我们先回答一个最简单的问题：

> Mihomo 到底在干什么？

---

## 一句话版本

你可以先把它理解成：

> **一个坐在你设备和互联网中间的「交通指挥员」。**

你的设备发出请求 → Mihomo 接到 → 它根据你写的规则判断「这条流量该怎么走」→ 然后帮你把连接建起来。

图示大概是这样：

```text
你的设备
   ↓
 Mihomo（判断 + 转发）
   ↓
代理节点（或者直连）
   ↓
目标网站 / 服务
```

它不是浏览器插件，也不是某个网站，而是一个**本地运行的程序**（核心）。很多客户端（FlClash、Clash Verge、Kumo、各种手机客户端）背后其实都在用它。

---

## 它是客户端还是服务端？

两个都能当。

- 跑在你电脑 / 手机上 → 通常当**本地代理核心**（最常见的用法）。
- 跑在服务器上 → 也可以当**代理服务端**，让别的设备连过来。

官方 wiki 里既有 outbound（出站，也就是你连出去用的节点），也有 inbound / listeners（入站，别人连你）。  
但对绝大多数新手来说，先把它当成「本地指挥员」就够了。

以后看到「Mihomo 客户端」这种说法，可以理解成：

> **使用 Mihomo 作为核心的客户端程序。**

而不是说 Mihomo 本身只能当客户端。

---

## 为什么需要它？

假设你手里有一堆节点：

- 日本
- 香港
- 新加坡
- 美国

你希望：

- 国内网站 → 直连
- Google / YouTube → 走代理
- 某个游戏 → 走香港
- 其他乱七八糟的 → 自动选延迟最低的

如果没有 Mihomo 这种东西，你就得每个软件单独设置代理，或者每次手动切换。非常痛苦。

Mihomo 的价值就在于：

> 把「接收流量 → 判断规则 → 选择节点 → 建立连接」这一整套流程统一管起来。

配置文件里那几个大块，其实就是在描述这几个步骤：

| 配置项 | 人话解释 |
| --- | --- |
| `proxies` | 我有哪些节点可以用 |
| `proxy-groups` | 这些节点怎么分组、怎么选 |
| `rules` | 什么流量走什么路线 |
| `dns` | 域名怎么解析成 IP |
| `tun` / `mixed-port` | 流量怎么进到 Mihomo 里 |

先把这张表记住，后面就不会那么容易晕。

---

## 先记住这一句就够了

> **Mihomo = 接收流量 → 按规则判断 → 选节点（或直连）→ 建立连接。**

其他细节，我们后面一点点拆。
