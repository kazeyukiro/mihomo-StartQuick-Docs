# Mihomo 到底是什么？

配置先放一边。先搞明白它在干什么。

---

设备要上网，请求先到 Mihomo，它按你写的规则决定：直连、丢掉，还是丢给某个代理节点。可以粗略想成夹在设备和外网中间的一道闸。

```text
你的设备
   ↓
 Mihomo（判断 + 转发）
   ↓
代理节点（或者直连）
   ↓
目标网站 / 服务
```

它不是浏览器插件，也不是网站，就是一个在本机或服务器上跑的程序。很多带窗口的客户端，底下调的就是它。

---

## 客户端还是服务端？

两边都能干。

本机、手机上跑，多半是给自己当本地代理。  
放到服务器上，也可以开入站，让别的设备连过来。

官方文档里 outbound 是你连出去的节点，inbound / listeners 是别人连你。新手先当「本机闸门」用就够了。

口头说的「某某 Mihomo 客户端」，一般是界面程序 + 底下的核心，不是说 Mihomo 只能当客户端。

---

## 为什么要有它？

节点多的时候，常见需求是：国内站直连、有的站走代理、游戏固定一条线、剩下的自动挑延迟低的。  
没有统一分流，就只能每个软件单独设，或者一天到晚手点切换。

Mihomo 把流程收成：收流量 → 对规则 → 选节点或直连 → 建连接。

配置文件里几大块大概对应：

| 配置项 | 干什么 |
| --- | --- |
| `proxies` | 有哪些节点 |
| `proxy-groups` | 怎么分组、怎么选 |
| `rules` | 什么流量走哪条路 |
| `dns` | 域名怎么解析 |
| `tun` / `mixed-port` | 流量从哪进 Mihomo |

后面章节就是在拆这些块。
