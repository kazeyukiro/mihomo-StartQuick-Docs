# Mihomo 到底是什么？

先别急着看配置。

先搞清楚一件事：

> Mihomo 到底在干什么？

---

## 一句话

可以先把它想成：

> **坐在你设备和互联网中间的交通指挥员。**

设备发出请求 → Mihomo 接到 → 按你写的规则判断这条流量怎么走 → 再去建连接。

```text
你的设备
   ↓
 Mihomo（判断 + 转发）
   ↓
代理节点（或者直连）
   ↓
目标网站 / 服务
```

它不是浏览器插件，也不是某个网站，而是一个在本机（或服务器上）跑的**程序核心**。  
很多带界面的客户端，背后调用的就是它。

---

## 客户端还是服务端？

两种用法都有。

- 跑在电脑 / 手机上：多半当**本地代理核心**（最常见）。
- 跑在服务器上：也可以当**代理服务端**，让别的设备连过来。

官方文档里既有 outbound（你连出去用的节点），也有 inbound / listeners（别人连你）。  
新手先按「本地指挥员」理解就行。

别人说「某某 Mihomo 客户端」，一般是指：**界面程序 + 底下的 Mihomo 核心**，不是说 Mihomo 只能当客户端。

---

## 为什么要有它？

手里一堆节点时，你可能希望：

- 国内站直连
- 有的站走代理
- 游戏走某一条线路
- 其余自动挑延迟低的

没有统一分流的话，就得每个软件单独设代理，或者天天手点切换。

Mihomo 把这件事收拢成一条流水线：

> 收流量 → 对规则 → 选节点（或直连）→ 建连接。

配置里几大块大致对应：

| 配置项 | 干什么 |
| --- | --- |
| `proxies` | 有哪些节点 |
| `proxy-groups` | 节点怎么分组、怎么选 |
| `rules` | 什么流量走哪条路 |
| `dns` | 域名怎么解析 |
| `tun` / `mixed-port` | 流量从哪进 Mihomo |

---

## 先记这一句

> **Mihomo = 接收流量 → 按规则判断 → 选节点（或直连）→ 建立连接。**
